# @pva/audio-file

Audio backends for tests and latency benchmarks on machines without a sound card.

- **`layerInput({ path, leadingSilenceMs?, trailingSilenceMs?, atEnd?, noiseFloor? })`**: an `AudioInput` that reads a `.wav` (16-bit PCM or 32-bit float, 16 kHz; multi-channel is averaged down to mono; float is converted to 16-bit) or raw `.pcm` file (16 kHz mono s16le) and emits 640-byte (20 ms) frames in real time, like a microphone. Frame `i` is emitted at `start + (i + 1) × 20 ms` on the monotonic clock, so pacing does not drift and works under `TestClock`. `atEnd: "silence"` keeps emitting silent frames after the file so a turn detector can fire; the default `"end"` ends the stream. `noiseFloor: true` fills the silences with white noise at about −75 dBFS instead of digital zeros, like a quiet microphone: the Silero VAD holds "speech" about 300 ms longer after long runs of exact zeros, which inflated benchmark latencies (the app turns it on). Other sample rates and formats are rejected with an `AudioError` (no resampling: convert with e.g. `sox in.wav -r 16000 -c 1 -b 16 out.wav`).
- **`layerOutput({ directory, prefix? })`**: an `AudioOutput` that "plays" in real time (a 2 s reply takes 2 s) and writes **one numbered file per `play` call**: `reply-001.wav`, `reply-002.wav`, ... Each `play` is one assistant reply, so a benchmark run can be listened to reply by reply and an interrupted reply is visibly cut short. An interrupted `play` returns at once and leaves a valid WAV with exactly what had been played. Numbering restarts at 1 for each layer instance and overwrites older files.
- **`parseWav` / `wavHeader` / `encodeWav`**: a small reader/writer for 16-bit PCM WAV (`parseWav` also reads 32-bit float).
