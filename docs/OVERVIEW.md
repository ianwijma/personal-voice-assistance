# Overview

How a turn flows through the assistant. The contracts are in [ARCHITECTURE.md](ARCHITECTURE.md).

## How it works

```
microphone ─pcm 16 kHz─▶ STT (local sherpa-onnx + Silero VAD, turn detection) ─events─▶ Conversation ─▶ LLM (Claude) + tools
     ─text─▶ clause chunker ─▶ TTS (local Piper, child process) ─pcm 22 kHz─▶ speaker
```

- Local models are loaded and warmed up at startup (about 1–2 s). Hosted connections open at startup and stay open; the LLM connection is warmed up.
- Text goes to TTS one clause at a time, as soon as each clause is complete, so the reply starts playing before the model has finished.
- **Speculative turns:** when the STT reports that you have *probably* finished (`EagerEndOfTurn`, after 250 ms of silence), the reply is generated right away but held back. If you really are done (`EndOfTurn`, 600 ms of silence), it plays at once. If you keep talking, it is thrown away. Only tools marked read-only run during speculation.
- **Barge-in:** if you start talking while the assistant is speaking, it stops. Only the part you actually heard is kept in the history.
- **Assistants and devices:** an **assistant** is a configuration you create in the admin page (`/admin/`): a prompt, a language model account and model, how it hears (speech model, turn timing), one voice and which modules it may use. A **device** (a browser today) says which assistants answer on it, which wake phrase wakes each one ("Hey Jeff", "Hey T3"), and who answers a sentence without a phrase: nobody, one assistant, or TypeSafe (hosted, optional) choosing from each assistant's description. Each device has its own conversation with each assistant, and several devices can talk at the same time. A **route gate** reads the transcript and picks the assistant; a **session dispatcher** keeps one conversation per assistant and one speaker per device; a **resource pool** shares what is equal (one language model instance, one loaded speech model, one voice) between assistants and devices and builds a changed one before switching, without a reload. Design, status and measurements: [docs/ASSISTANTS.md](ASSISTANTS.md); the protocol (version 7) is in `packages/protocol`.

## Status

> The local pipeline (speech in → recognised → turn detected → reply generated by the offline stand-in model → synthesised → written to WAV) has run end to end on the development machine, and so has the web UI: the real page in headless Chromium, with a fake microphone fed from WAV files, against the real assistant (`pnpm e2e:real`). It has **never** run with a real microphone and speaker (no sound card), never on a real laptop or phone, and never against the real Anthropic, Deepgram or Cartesia services (no keys). See [VERIFICATION.md](VERIFICATION.md).
