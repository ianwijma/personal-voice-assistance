## 1. Consuming `packages/protocol` (TS source, `.ts` imports, ESM) [run]

- **`transpilePackages` is not required.** `next dev` (Turbopack), `next build` (Turbopack) and `next build --webpack` all compiled with it
  removed, because pnpm symlinks resolve to `packages/protocol`, outside `node_modules`. Keep `transpilePackages: ["@pva/protocol"]` anyway:
  it is the documented monorepo setting, costs nothing, and keeps working if the package is ever installed from a registry.
- **`.ts` specifiers inside the package (`export * from "./messages.ts"`) resolve fine** in Turbopack and webpack. No `extensionAlias`, no loader.
- `tsconfig`: needs `allowImportingTsExtensions` (already in `tsconfig.base.json`, legal because `noEmit`), `moduleResolution: "bundler"`,
  `module: "esnext"`, `jsx: "react-jsx"`, `lib` with `dom`. The workspace base uses `module/moduleResolution: NodeNext`, which is wrong for Next; override both.
- **No conflicts** with `exactOptionalPropertyTypes`, `verbatimModuleSyntax`, `noUncheckedIndexedAccess`, `erasableSyntaxOnly`, `isolatedModules`
  under TS 7.0.2: `tsc -p apps/web/tsconfig.json` is clean and `next build` ("Running TypeScript") passes. `next build` did **not** rewrite `tsconfig.json`.
- **Pitfall (verified failure): the root `pnpm check` will break.** Root `tsconfig.json` includes `apps/*/src`, so it picks up `apps/web/src` with NodeNext, no DOM
  and no JSX: 41 lines of errors (`Cannot use JSX unless '--jsx'`, `Cannot find module '@/lib/store.ts'`). Fix: add `"exclude": ["apps/web"]` to the root `tsconfig.json`
  and make the root `check` also run the web check (e.g. `tsc -p tsconfig.json && pnpm --filter @pva/web check`). With the exclude, root `tsc` is clean.
- `LayoutProps<"/">` (used by the template's layout) is a global generated by `next typegen`/`next dev`; a plain `tsc` before the first dev run fails on it.
  Use `{ children: ReactNode }` instead.
- `src/worklets/` must be excluded from the web `tsconfig` (they are worklet-scope files; the DOM lib has no `AudioWorkletProcessor`/`registerProcessor`).

## 2. Effect in browser client components [run]

Verified in Chromium (Playwright) against a real `ws` server, in `next dev` and in `next start`:

- Schema decode of JSON text frames (`Schema.decodeUnknownEffect(Schema.fromJsonString(ServerMessage))`); a deliberately bad frame is counted, not fatal.
- `Socket.makeWebSocket` (`effect/socket/Socket`, marked `@stability unstable`) over the browser's global `WebSocket` via `Socket.layerWebSocketConstructorGlobal`; it sets `binaryType = "arraybuffer"` itself; text frames arrive as `string`, binary as `Uint8Array`.
- A long-lived fiber: `Effect.runFork(program)`; unmount does `Effect.runFork(Fiber.interrupt(fiber))`. React StrictMode double-mount (default in dev) did not leave two connections.
- Reconnect: `Effect.retry(Schedule.min([Schedule.exponential("250 millis"), Schedule.spaced("5 seconds")]))` (250 ms doubling, capped at 5 s, forever).
  Test result: server killed, UI shows `reconnecting #4` after 3 s; server restarted, `open #0` again 763 ms later.
- v4 API differences that bit me: no `Schedule.either` (use `Schedule.min([...])`, array arg); `Effect.match` takes `{ onSuccess, onFailure }`; `Socket` exposes `reader`/`writer` (batched `pull`), there is no `socket.run` in 4.1.4; subpath imports are `effect/socket/Socket`, `effect/reactivity/Atom`.

### The bridge: a plain store + `useSyncExternalStore` (recommended)

`src/lib/connection.ts` (Effect side, framework-free: it only needs an `update(f)` callback):
```ts
import { Duration, Effect, Fiber, Schedule } from "effect"
import * as Socket from "effect/socket/Socket"
import { decodeServerMessage, type ServerMessage } from "@pva/protocol"

export type Status = "connecting" | "open" | "reconnecting"

export interface ClientState {
  readonly status: Status
  readonly attempt: number
  readonly assistant: "idle" | "listening" | "thinking" | "speaking"
  readonly transcripts: ReadonlyArray<{ readonly id: string; readonly text: string; readonly final: boolean }>
  readonly binaryBytes: number
  readonly badFrames: number
}

export const initialState: ClientState = {
  status: "connecting", attempt: 0, assistant: "idle", transcripts: [], binaryBytes: 0, badFrames: 0
}

export type Update = (f: (s: ClientState) => ClientState) => void

const reduce = (m: ServerMessage) => (s: ClientState): ClientState =>
  m.type === "state"
    ? { ...s, assistant: m.state }
    : { ...s, transcripts: [...s.transcripts.filter((t) => t.id !== m.id), { id: m.id, text: m.text, final: m.final }] }

/** One connection attempt: open, read frames until the socket fails. Never succeeds. */
const session = (url: string, update: Update) =>
  Effect.scoped(Effect.gen(function*() {
    const socket = yield* Socket.makeWebSocket(url, { openTimeout: Duration.seconds(5) })
    const { pull } = yield* socket.reader
    update((s) => ({ ...s, status: "open", attempt: 0 }))
    while (true) {
      const batch = yield* pull
      for (const frame of batch) {
        if (typeof frame === "string") {
          yield* decodeServerMessage(frame).pipe(
            Effect.match({
              onSuccess: (m) => update(reduce(m)),
              onFailure: () => update((s) => ({ ...s, badFrames: s.badFrames + 1 }))
            })
          )
        } else {
          update((s) => ({ ...s, binaryBytes: s.binaryBytes + frame.byteLength }))
        }
      }
    }
  }))

const program = (url: string, update: Update) =>
  session(url, update).pipe(
    Effect.tapError(() => Effect.sync(() => update((s) => ({ ...s, status: "reconnecting", attempt: s.attempt + 1 })))),
    Effect.retry(Schedule.min([Schedule.exponential("250 millis"), Schedule.spaced("5 seconds")])),
    Effect.provide(Socket.layerWebSocketConstructorGlobal)
  )

/** Start the long-lived connection fiber. Returns a stop function. */
export const startConnection = (url: string, update: Update): (() => void) => {
  const fiber = Effect.runFork(program(url, update) as Effect.Effect<never, unknown>)
  return () => { Effect.runFork(Fiber.interrupt(fiber)) }
}
```
(`Socket.makeWebSocket` closes the browser socket with code 1000 when the scope closes, so interrupt cleans up.)

`src/lib/store.ts`:
```ts
import { useSyncExternalStore } from "react"
import { initialState, type ClientState } from "./connection.ts"

export interface Store<T> {
  readonly get: () => T
  readonly subscribe: (l: () => void) => () => void
  readonly update: (f: (s: T) => T) => void
}

export const createStore = <T>(initial: T): Store<T> => {
  let state = initial
  const listeners = new Set<() => void>()
  return {
    get: () => state,
    subscribe: (l) => { listeners.add(l); return () => { listeners.delete(l) } },
    update: (f) => { const next = f(state); if (next !== state) { state = next; listeners.forEach((l) => l()) } }
  }
}

export const clientStore = createStore<ClientState>(initialState)

export const useStore = <T,>(store: Store<T>): T =>
  useSyncExternalStore(store.subscribe, store.get, store.get) // 3rd arg = server snapshot, required for SSR
```

### Alternative: `@effect/atom-react` [run, minimal use only]

```tsx
"use client"
import { useContext, useEffect } from "react"
import { RegistryContext, useAtomValue } from "@effect/atom-react"
import * as Atom from "effect/reactivity/Atom"
import { initialState, startConnection, type ClientState } from "@/lib/connection.ts"

const stateAtom = Atom.make<ClientState>(initialState).pipe(Atom.keepAlive)

export function AtomAssistant({ url }: { readonly url: string }) {
  const registry = useContext(RegistryContext)
  const s = useAtomValue(stateAtom)
  useEffect(() => startConnection(url, (f) => registry.set(stateAtom, f(registry.get(stateAtom)))), [url, registry])
  return <p>{s.status}</p>
}
```
Worked in dev and production (SSR, hydration, updates). The default `RegistryContext` registry exists without a provider; no `"use client"` boundary problem because the package files carry their own.
It imports `scheduler` (React's internal scheduler) directly: `unstable_scheduleCallback`.

### Comparison and recommendation

| | Hand-written store | `@effect/atom-react` |
|---|---|---|
| Client JS added over a React+Next baseline (`/_not-found`), raw / gzip | see table below | **+40 KB raw / +14 KB gzip** more than the store page |
| API stability | `useSyncExternalStore` is React core; the store is 15 lines you own | package and `effect/reactivity` are `@stability unstable`; Socket is too |
| Re-render control | whole-state snapshot; add selectors if the screen grows | fine-grained atoms, derived atoms, TTL/keep-alive rules to learn |
| Surface used in spike | 3 exports | `Atom.make`, `keepAlive`, `RegistryContext`, `useAtomValue` |

**Recommendation: hand-written store with `useSyncExternalStore`.** The Effect code (connection, decoding, retry) stays framework-free and only sees `update(f)`; the React side has no dependency
with an unstable API; it is ~40 KB lighter. Switch to atoms only if the UI grows many independent derived values. The audio visualiser should bypass both (a plain mutable object read on `requestAnimationFrame`).

## 3. Tailwind 4 as generated [run]

- `create-next-app@16.4.6 --ts --tailwind --app --src-dir --turbopack` produces: `src/app/globals.css`, **no `tailwind.config.*`, no `postcss.config.*`**,
  `@tailwindcss/turbopack` + `tailwindcss` devDependencies, and the `turbopack.rules` entry shown above. (It also runs `next/font/google` for Geist; I removed that, so the build needs no network.)
- CSS entry is `@import "tailwindcss";` (not `@tailwind base/components/utilities`). Theme tokens live in CSS: `@theme { --color-accent: ...; --font-sans: ...; --animate-pulse-ring: ...; @keyframes ... }`
  generates utilities `bg-accent`, `text-accent`, `animate-pulse-ring`, `font-sans`. **Verified in the served CSS**: the variables, the `@keyframes pulse-ring` and the utilities were emitted.
- `@theme inline { --color-background: var(--background) }` (what the template uses) is for tokens that reference other variables; without `inline`, utilities would reference the theme variable
  rather than inlining the referenced one. Plain values go in plain `@theme`.
- Dark mode: **by default `dark:` follows `prefers-color-scheme`** (the template flips `--background` in a `@media (prefers-color-scheme: dark)` block). A class/attribute toggle requires
  `@custom-variant dark (&:where(.dark, .dark *));` [doc: Tailwind 4 docs, from memory, **not run here**].
- Differences to get right from memory: no JS config file (`content` paths are detected automatically from the project; there is no `content:` array); tokens are CSS variables so you can read them in `canvas`/JS with
  `getComputedStyle(document.documentElement).getPropertyValue("--color-accent")` (the colour came out as `lab(54.2137% 9.38562 -66.5)` for the `oklch(...)` I wrote: Tailwind emitted both a hex and a `lab()` fallback);
  `size-16` and `min-h-dvh` compiled and rendered in the spike; the template's `bg-white dark:bg-black` pairs are the dark-mode idiom (from the template source, not re-tested). The built-in palette being OKLCH is from memory [unverified].

## 4. AudioWorklet scripts [run, dev and `next build` + `next start`, in headless Chromium]

Three ways tested on a `/worklet` page that calls `audioWorklet.addModule(...)`, creates the node, posts `"ping"` and waits for the reply:

| Method | Dev | Production | Result |
|---|---|---|---|
| Plain JS in `public/worklets/capture.js`, `addModule("/worklets/capture.js")` | works | works | served as `application/javascript` |
| Plain **JS** at `src/worklets/playback.worklet.js`, `addModule(new URL("../../worklets/playback.worklet.js", import.meta.url))` | works | works | Turbopack treats it as an asset: copied to `/_next/static/media/playback.worklet.<hash>.js`, **not bundled, not transformed**, `application/javascript` |
| **TypeScript** at `src/worklets/typed.worklet.ts` through `new URL(...)` | **fails** | **fails** | copied verbatim (types and all) as `typed.worklet.<hash>.ts`, served as `video/mp2t`: `AbortError: Failed to load worklet module script ... (MIME type mismatch)` |

Conclusions:
- `new URL("./x.ts", import.meta.url)` under Turbopack is only an asset reference; it does **not** compile TypeScript and cannot `import` other modules (the copied file has its imports untouched and unresolved).
- **Recommendation: plain JavaScript in `apps/web/public/worklets/*.js`**, loaded by absolute path `"/worklets/capture.js"`. Simplest, identical in dev, `next start` and static export, no hashing (add a version query like `?v=1` if you care about stale caches),
  and the file runs exactly as written. Types: add `// @ts-check` plus a `declare` shim, or keep worklets tiny; a TS worklet would need a separate esbuild/tsc step (not tested).
- Worklet scope has no `import` of `effect`/workspace packages unless bundled; keep processors dependency-free (ring buffer + `postMessage`).
- `addModule` works on a **suspended** `AudioContext`; the context only becomes `running` after a user gesture (`ctx.state` was `suspended` before, `running` after `resume()` in the mic test).
- Static export (section 5) copies both the `public/` script and the `_next/static/media` JS asset.
- `new Worker(new URL("./w.ts", import.meta.url))` (the form Turbopack does bundle) was **not tested [unverified]**; it does not apply to AudioWorklet anyway.

### Reaching it from another device (secure context needed for `getUserMedia`) [run]
- Plain `http://192.168.1.67:3000` is **not** a secure context: in Chromium `isSecureContext === false` and `navigator.mediaDevices === undefined`, so no microphone. (Verified; `http://localhost` is secure.)
- **`next dev --experimental-https` (default) did not work here**: it downloads mkcert v1.4.4 into `~/.cache/mkcert/`, runs `mkcert -install` (wants to install a CA into the system trust store, may prompt for sudo),
  and when that failed it **printed an error and silently fell back to plain HTTP** (`Local: http://localhost:3103`, `https://` curl returned 000). It leaves `~/.cache/mkcert` and `~/.local/share/mkcert` behind (I removed both). I did not diagnose why `mkcert -install` failed.
- **Working variant: bring your own cert** with `next dev --experimental-https --experimental-https-key key.pem --experimental-https-cert cert.pem`. Verified: `https://localhost:3104` and `https://192.168.1.67:3104` returned 200 (curl `-k`, and with `--cacert cert.pem`).
  Generated with `openssl req -x509 -newkey rsa:2048 -nodes -days 30 -keyout key.pem -out cert.pem -subj "/CN=localhost" -addext "subjectAltName=DNS:localhost,IP:127.0.0.1,IP:<lan-ip>"`.
  A self-signed cert still shows a browser warning on the other device (accept it once, or install the cert/CA there); that was **not tested on a real second device** [unverified]. `*.pem` is gitignored by the template.
- **`allowedDevOrigins` is needed when you open the dev server by LAN IP or hostname** (Next 16): dev-only endpoints return 403 for other origins. Verified: `Origin: https://192.168.1.67:3104` -> 403 and `Origin: https://phone.lan:3104` -> 403, `Origin: https://localhost:3104` -> allowed.
  The log prints the fix: `allowedDevOrigins: ["192.168.1.67"]` (hostname only, no scheme or port; wildcards `*.x` / `**.x` allowed). Whether HMR then works over the LAN was not exercised [unverified].
- The assistant WebSocket must also be secure when the page is `https://` (`wss://`); not tested with TLS **[unverified]**.
- **Alternative: SSH port forwarding** [not run, standard]: `ssh -L 3000:localhost:3000 -L 8787:localhost:8787 host`; the client browser then sees `http://localhost:3000`, which is a secure context, no certificate needed. Works for one dev; not for a phone unless it can run an SSH client with forwarding.
- Tailscale/real-domain certificate options are in `docs/research/browser-audio.md` and were not tested here.

## 6. Testing: vitest + jsdom [run, 2 passing tests]

## Pitfalls (checklist)

1. Root `tsconfig.json` must exclude `apps/web`; the web app needs its own `tsconfig.json` (bundler resolution, DOM, JSX). Make root `check` run both.
2. Root vitest config needs `projects` (node + `apps/web` with jsdom); a single node-env include will pick up web tests wrongly.
3. `--experimental-https` alone may fall back to HTTP without failing; pass `--experimental-https-key/--cert` and look for `https://` in the printed URL.
4. Dev server accessed by LAN IP/hostname needs `allowedDevOrigins` (403 otherwise).
5. TS worklets via `new URL(..., import.meta.url)` are copied raw and served as `video/mp2t`: do not do this. Use `public/worklets/*.js`.
6. `create-next-app` (this version) brings `cacheComponents`, `partialPrefetching`, `next/font/google` (needs network at build), and an `AGENTS.md`/`CLAUDE.md`-style block pointing at `node_modules/next/dist/docs/`. Remove the first three if unwanted; `AGENTS.md` is re-added by `next dev` per its text.
7. `LayoutProps<"/">` only exists after typegen; use explicit prop types so `tsc` works on a clean checkout.
8. `useSyncExternalStore` needs the third (server snapshot) argument in a client component that is SSR'd (Next prerenders it).
9. Effect 4 API differs from v3 (`Schedule.min([...])`, `Effect.match`, `Socket` reader/writer); read `node_modules/effect/src/socket/Socket.ts` and `ai-docs`. Socket and Atom modules are `@stability unstable`.
10. A client component that imports `@pva/protocol` also ships `effect` Schema to the browser: ~+242 KB raw / +81 KB gzip. Keep server-only code (anything using node APIs) out of `protocol`.
11. Killing only the parent `pnpm` process of `pnpm dev` leaves children running.
12. Tailwind 4: `@import "tailwindcss"`, `@theme` for tokens, no config file; class-based dark mode needs `@custom-variant` (not verified here).
13. `next build` writes `tsconfig.tsbuildinfo` (gitignored by `*.tsbuildinfo`) and `.next/`; `next-env.d.ts` is generated.
